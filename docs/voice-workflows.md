# Voice workflows

The initial builder was verified with a harmless JSON import/preview/wait fixture. The expanded Mac update passes 150 regression tests, including hotkey ownership, immediate execution and display-fallback policy. Live spoken-command recognition remains user acceptance. See status.md for evidence.

A workflow has a name, an exact spoken phrase, an enabled switch, and an ordered list of actions. Use the dedicated **Record command** control in Workflows. Ordinary dictation, meetings, imported recordings and History retry do not run workflows. There is no always-listening wake word. A unique enabled phrase must match the recognized text, ignoring case, punctuation and repeated spaces. An ambiguous or unmatched phrase does nothing. Press **Control–Shift–Space** to start recording and press it again to finish; the familiar recording overlay shows progress. Customize Voice workflow in Configuration. A unique enabled match runs immediately without a confirmation dialog. Manual Preview / Run retains its review.

The initial action blocks are **Open app**, **Open website**, **Search web**, and **Wait**. Steps execute sequentially; a failure stops the remaining steps. Cancellation stops subsequent steps but does not undo apps or pages already opened. Open app can optionally move its window to a physical display and enter fullscreen using public macOS Accessibility controls. Main display is first; other displays use display-ID order. A disconnected display target falls back to the main display. Enable Accessibility for JustWisper in System Settings to place windows. Existing fullscreen windows leave fullscreen before a requested display move. Fullscreen creates a Space whose number macOS controls; choosing an arbitrary numbered Space is unavailable. Window readiness and fullscreen waits are bounded, and cancellation skips subsequent work. This version does not close windows, discard documents, execute shell commands or scripts, or automatically start ChatGPT Voice. OpenAI's [voice walkthrough](https://developers.openai.com/training/walkthroughs/using-voice) documents starting Voice from the app interface; an external Voice-start integration has not been verified.

## Sharing

Copy JSON exports a versioned document containing one workflow and its action values. Paste it into the import area, review the steps, and import it. Import gives the workflow and actions new identities and leaves it disabled. Enable it explicitly after review. Importing never executes actions. Unsupported versions/action kinds, invalid fields and oversized documents are rejected. JSON is data, not executable code.

The first schema uses `version: 1`, a `workflow` object, and an `actions` array. Each action has a `kind` and `value`, with generated identities used by the editor. Supported kinds are `openApp`, `openURL`, `webSearch` and `delay`. App actions use a bundle identifier internally and resolve an installed app. Website actions accept HTTPS URLs without credentials, query strings or fragments. Search actions send their configured search text to Google in the default browser. Wait accepts zero to thirty seconds, with sixty seconds maximum per workflow. A workflow permits up to twenty actions; imports are limited to 64 KiB, with at most one hundred saved workflows.

Workflow exports omit app credentials and transcript History, but values entered by the author are included verbatim. Review them before sharing; a website path or search term can contain private information. Do not put credentials into action values. Opening a page may use the browser's existing signed-in session.

## Storage and recognition

Workflows are stored in the app library, covered by transcript-library encryption when that option is enabled. They are not automatically added to configuration sync. Explicit JSON sharing is separate from encryption. Command audio uses the selected speech provider: local recognition stays local, while a configured cloud speech provider receives audio. Recognition and audio-retention behavior should be reviewed before use. No general-purpose AI planner or downloaded tool server is needed to run these fixed action blocks.

### Alternative phrases, spoken searches, and browser profiles (macOS)

The workflow editor offers **Add more phrases** below the primary exact voice phrase. Each workflow accepts up to 20 distinct phrases. Alternatives can be edited or removed and are included in library storage and shared JSON; old workflows keep their original phrase. If more than one enabled workflow matches, none runs.

New Search web actions use `{query}` by default. Say any saved trigger followed by your search text in **Record command**, for example `search web C++ tutorials`. Cortala inserts the trailing spoken text into `{query}`, encodes it as Google's query parameter, and runs the workflow immediately. You can include fixed text around the placeholder or replace it entirely with a fixed search. Existing fixed searches stay fixed. A workflow requiring `{query}` cannot run from Preview / Run without spoken text; missing query text stops it before any actions execute. Ordinary dictation does not execute workflows.

Search web and Open website have a Browser picker. Open app uses the chosen app's bundle ID. Chromium browsers (Chrome, Chrome Beta, Edge, Brave, Chromium) and Firefox expose a Browser profile picker, including for Open app. Chromium profile names come from Local State and existing profile directories; Firefox names come from profiles.ini. Profile IDs are stored rather than absolute paths. Browser default lets the browser choose; an explicitly selected missing profile or browser produces an error instead of silently choosing another profile. Safari uses its default profile; named Safari profiles are not supported. Profile arguments are delivered through a new application launch request, including when the browser is already running. Browser-specific behavior still needs interactive acceptance on each browser/version.

A captured query supports up to 10 search subjects. The Search web action includes an editable **Search separator word or phrase**, saved with the action. It defaults to `and about`: for a workflow whose trigger is `search for`, say `search for Winnie the Pooh and about Tom and Jerry`. Two search URLs open sequentially in the selected browser/profile. Separators are literal, case-insensitive words/phrases surrounded by whitespace. You may deliberately choose `and`, but then `Tom and Jerry` becomes two searches. Fixed saved searches do not split. Browser settings ultimately control tab-versus-window presentation; Cortala supplies a separate URL-opening request for every subject. If a subject itself contains your separator phrase, record that search separately or choose a different separator.
